**Problem:** Develop a novel cache replacement policy for application-level caches (CDN edge caches, database buffer pools, web caches, object stores) that beats current state-of-the-art (LRU, ARC, S3-FIFO, SIEVE) in hit rate at small cache sizes (0.1% to 10% of unique objects in the working set) on realistic workloads (Twitter cluster traces, SNIA MSR Cambridge block traces, Wikipedia CDN trace). The bottleneck: existing policies face a trilemma between (i) simplicity (LRU is O(1) per access but doesn't adapt to access patterns), (ii) adaptivity (ARC adapts but has 2 LRU lists and is hard to make lock-free), and (iii) accuracy (LeCAR / learned policies do better but need RL state and online training). SIEVE (OSDI 2024) achieved high hit rates with a single visited bit per cache entry, suggesting that very small amounts of metadata can encode informative signals; S3-FIFO (SOSP 2023) showed that a small probationary FIFO can filter scan-resistant workloads. The remaining headroom: most policies still treat all object types identically, ignore inter-object correlations (object A access → object B soon), and don't exploit cheap probabilistic structures that have become standard elsewhere. **Synthesis claim:** P8's constrained temporal scheduling + P45's next-event prediction + P21's high-rate trigger filtering suggests a time-to-next-use eviction scheduler: predict each cached object's next request window, then evict the object whose scheduled future contribution is weakest under capacity. This approximates Belady-style replacement using cheap predictors and can be benchmarked as a pure Python policy with decayed next-use estimates rather than neural inference.

**Compatibility argument:** Scheduling and caching both allocate scarce capacity over time. P8 supplies the constrained temporal allocation frame, P45 supplies the history-based prediction principle, and P21 supports the idea of filtering high-rate streams to retain valuable events. The cache version would avoid ILP in the hot path by using rolling priority scores.

- L3 adversarial check: **INVALID** — The composition collapses into a well-known idea: approximate Belady by predicting next reuse and evicting the item with the weakest/most distant future value. That is not meaningfully derived from P8, P45, or P21, and the cited papers do not supply the missing cache-specific machinery: an online, cheap, accurate next-use predictor under tiny metadata budgets. P8 is an offline constrained scheduler with known candidate observations and ILP-scale planning, P45 is a heavyweight neural sequence model rather than a cheap next-event estimator, and P21 is a domain-specific trigger-efficiency study, not a general high-rate cache filtering method. The proposal names the right aspiration but leaves the central hard part unsolved and is not novel relative to Belady approximations, reuse-distance prediction, Hawkeye-style policies, learned cache replacement, and frequency/recency hybrids.
  - [WOULD INVALIDATE] Folklore Belady Approximation: Evicting the cached object with the farthest or weakest predicted next use is exactly the standard framing behind Belady-style replacement approximations. Many cache papers already use reuse-distance, next-access prediction, or learned replacement scores to approximate OPT. The proposed policy is therefore not a new bridge from scheduling, transformers, and trigger filtering; it is a restatement of a central cache-replacement objective.
  - [WOULD INVALIDATE] P45 Mischaracterized: Attention Is All You Need does not provide a cheap history-based next-event predictor suitable for pure Python cache replacement. It proposes the Transformer architecture for sequence transduction, trained on large translation corpora using substantial compute. The composition extracts the vague idea that sequence history can predict future tokens, but that is far weaker than supplying an implementable, low-overhead predictor for object reuse windows.
  - [WOULD INVALIDATE] P8 Offline Scheduler Mismatch: The ZTF scheduler solves an offline or batch optimization problem over a known night of candidate observations with explicit constraints and objective terms. Cache replacement is online, adversarially interleaved, and must decide at every miss without knowing the future request stream. Replacing the ILP with rolling priority scores removes the actual mechanism P8 contributes, leaving only the generic statement that scarce capacity can be scheduled over time.
  - [WOULD INVALIDATE] P21 Does Not Support Cache Filtering: The ATLAS trigger paper reports performance of domain-specific detector triggers under physics thresholds and luminosity conditions. It does not establish a reusable algorithmic principle for cache admission or eviction, nor does it show that high-rate filtering preserves future utility in a nonstationary object-request stream. Invoking it as support for valuable-event retention is mostly metaphorical.
  - [WOULD INVALIDATE] Missing Predictor: The proposal says to predict each cached object's next request window using decayed next-use estimates, but that is the core research problem, not an implementation detail. It does not specify the state representation, update rule, confidence handling, cold-start behavior, object correlation model, aging strategy, or how to avoid overfitting scans and bursts. Without this, the policy is just 'score objects well and evict the low score one.'
  - [WOULD INVALIDATE] Metadata Budget Conflict: The problem emphasizes small metadata and simple hot-path behavior, but predicting next-use windows for every cached object can require timestamps, intervals, per-object histories, confidence estimates, and possibly cross-object correlation tables. That likely exceeds the one-bit or small-FIFO simplicity that made SIEVE and S3-FIFO attractive. If the metadata is aggressively compressed, the claimed next-use accuracy is unsupported.
  - [WOULD INVALIDATE] Correlation Claim Unused: The problem statement highlights inter-object correlations, but the proposed policy only predicts each cached object's next request window. Unless it also admits or retains B because A was seen, it does not really exploit A-to-B correlations. If it does add such prediction, it becomes a prefetch/admission/correlation-mining policy with additional machinery not described by the composition.
  - [challenge] Benchmark Risk at Small Caches: At 0.1% to 1% cache sizes, most objects are absent, many cached items have sparse histories, and scans can dominate admission pressure. A decayed next-use estimator may perform worse than S3-FIFO or SIEVE because those policies cheaply filter one-hit objects, while next-use estimates for rare objects are noisy or unavailable. The proposal does not explain why its predictions should be reliable specifically in the small-cache regime.
  - [challenge] Cost Hidden in Priority Maintenance: Evicting the object with weakest scheduled future contribution implies maintaining a priority structure whose keys change as time advances and estimates decay. That is not obviously O(1), and lazy heap updates can accumulate stale entries. The proposal claims cheap rolling priority scores but does not reconcile this with the simplicity target or lock-free implementation concerns raised against ARC.
