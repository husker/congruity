# Computable packs real-data test - short HTTP headers

**Date:** 2026-05-31
**Purpose:** Test the new computable-pack framework on a real local dataset,
not only schema/unit tests.
**Pack:** `short_string_compression`
**Dataset:** `data/real_http_headers.json`

## Question

Can the new computable-pack layer route a real problem to the right pack, prove
the pack is executable, and run a real benchmark against strong baselines?

Problem text used for routing:

> Can we find a better lossless compressor for real HTTP response headers than
> HPACK, Brotli dictionaries, and Zstandard dictionaries?

## Real HTTP results

Lower `ratio_total` is better.

### Leakage-prone shuffled line split

| method | ratio_total | median | p99 expansion |
|---|---:|---:|---:|
| C2-proto | 0.5668 | 0.5761 | 1.3000 |
| hpack-stateful | 0.6099 | 0.6522 | 0.9091 |
| C1-proto | 0.6490 | 0.1942 | 1.1000 |
| C3-proto | 0.6625 | 0.7059 | 1.2000 |
| hpack-static | 0.6866 | 0.7353 | 0.9130 |
| zstd-19+dict | 0.7444 | 0.8462 | 2.3000 |
| brotli-11 | 0.9613 | 1.1143 | 1.4000 |

C2-proto beats the strongest listed baseline, HPACK-stateful, by 7.07%
relative total compression ratio on this split.

### Leakage-free site split

C2-proto beats HPACK-stateful by 7.83% relative total compression ratio on the
site split.

## Verdict

The computable-pack framework passed this real-data trial:

- `match` routed the natural-language problem to `short_string_compression`.
- `preflight` correctly reported the selected pack as AI-verifiable.
- The pack command ran to completion on a local real HTTP header dataset.
- The benchmark produced a concrete, machine-checkable result against HPACK,
  Brotli, and Zstandard dictionary baselines.

The result is a real positive for the short-string benchmark path, especially
because the leakage-free site split still clears HPACK-stateful by 7.83%.

## Caveats

- This tests pack routing and executable verification, not a fresh compose run.
- C2-proto is an existing local prototype, not newly generated by this test.
- HPACK has better p99 expansion than C2-proto on real HTTP splits, so the win
  is on total compression ratio, not tail expansion.
- The current framework still relies on pack authors to provide true commands;
  command execution is not yet part of `preflight`.
